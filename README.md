## 3. Project Overview

The objective of this project is to develop a machine learning system that predicts ATM cash withdrawal demand in Dehradun.

The project follows an end-to-end MLOps workflow covering:

- Data investigation and quality assessment
- Data versioning using DVC
- Data loading, cleaning, and preprocessing
- Machine learning model development
- Experiment tracking and evaluation
- API development and testing
- Containerization and deployment
- Model monitoring and retraining

## 4. Dataset Description

The project uses three datasets:

| Dataset | Description | Records |
|---|---|---:|
| `train.csv` | Historical training dataset | 1000 |
| `later.csv` | Later-period dataset for monitoring and further analysis | 300 |
| `holdout_features.csv` | Holdout dataset for final predictions | 250 |

**Prediction target:** `withdrawal_thousand_rs`

The holdout dataset does not contain the target column.

### Original Dataset Columns

- `record_id`
- `date`
- `nearby_shops`
- `days_to_salary`
- `footfall_index`
- `distance_to_market_km`
- `avg_ticket_rs`
- `other_atms_1km`
- `atm_type`
- `area`
- `withdrawal_thousand_rs` (not available in holdout)

## 5. Data Investigation Findings

The initial investigation identified the following data-quality issues:

| Data issue | Finding | Action |
|---|---|---|
| Data leakage | No leakage identified during initial investigation | No action required |
| Unit inconsistency | Highway distances in training data were recorded in metres | Converted to kilometres |
| Sentinel values | `avg_ticket_rs` contains -999 in 54 training records | Replaced with missing values |
| Duplicate rows | No duplicate rows identified | No rows removed |
| Stuck sensor / suspicious values | `days_to_salary` contains repeated values of 22 | Retained without modification |
| Target anomalies | No 10× target typo group identified | No correction required |
| Category inconsistencies | `atm_type` contains spelling and formatting variants | Normalized into three categories |

Detailed findings are documented in `findings.yaml`.

## 11. Data Preprocessing

The preprocessing pipeline performs the following operations:

1. Cleans the input datasets.
2. Converts Highway distances from metres to kilometres in the training data.
3. Replaces the `-999` sentinel value in `avg_ticket_rs` with missing values.
4. Normalizes ATM type categories.
5. Handles missing numeric values using medians calculated from training data.
6. Encodes categorical features consistently.
7. Retains `record_id` and `date` as metadata.
8. Ensures consistent feature columns across train, later, and holdout datasets.

The target column is kept separately from the model features.

### Run preprocessing directly

```bash
python -m src.mp293.prepare_data
```

### Run preprocessing using DVC

The project uses a DVC pipeline defined in `dvc.yaml`.

Run:

```bash
python -m dvc repro
```

DVC checks dependencies and executes the preprocessing stage when required.

To force execution again:

```bash
python -m dvc repro --force
```

### Generated Outputs

The pipeline generates the following files inside `data/processed/`:

| Output file | Shape |
|---|---:|
| `train_processed.csv` | 1000 × 15 |
| `later_processed.csv` | 300 × 15 |
| `holdout_processed.csv` | 250 × 14 |
| `preprocessor.json` | Preprocessing configuration |

The processed datasets contain metadata and prepared features. The training and later datasets also contain the target column.
